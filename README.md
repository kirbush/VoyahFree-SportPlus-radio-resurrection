# VoyahFree-SportPlus-radio-resurrection

Восстановление аппаратного FM-радио на Voyah Free Sport Plus после перехода на китайскую прошивку.

Текущая версия — **0.5.0-beta**, versionCode 8: одно приложение и установщик для Windows.

- **FM Радио** открывает штатный экран радио с оригинальной иконкой. Шестерёнка справа вверху открывает настройки на том же экране.
- В меню: **«Отправить логи»**, **«Сохранить ZIP»** в Downloads и **«Автоотправка раз в 30 минут»**. Журналы записываются автоматически; сеть обслуживается отдельно от радио.
- Установщик через ADB сохраняет настройки и отчёты, удаляет прежнее отдельное приложение «FM Диагностика». Приватный `upload.json` передаётся отдельно; установщик отчёты не отправляет.

На российской прошивке уже установленные OEM APK остаются побайтно прежними. Наш отдельный пакет использует существующий RDS-процесс и FM-тракт, поэтому шестерёнка может появляться и через родной значок радио. Это не два независимых радиоприёмника.

Нужны аппаратный FM-блок, совместимое ГУ Android 11/API 30 и работающий VoyahTweaks с используемым каналом root-запуска. Комплект хранится в `/data`; системные разделы и файлы автозапуска Tweaks не изменяются.

## Состояние проверки

У внешнего тестера предыдущая версия восстановила звук и работала после полной перезагрузки без ПК. Его точная прошивка — `EB.01.20260530180528.rc1.1.user.f6802h`, build 18; по имеющимся сведениям это 7.2.0. Образ 7.3.1 проверен статически, испытание этой версии на машине пока не подтверждено.

В дополнительном отчёте второго тестера найден стек падения RdsApp: повторная регистрация DisplayUtils$1 observer. В 0.5.0 добавлен точечный guard, исправлены флаги запуска и переход в отдельную диагностику заменён меню внутри RDS. Отчёт дополнен crash buffer/DropBox. Проверены 25 локальных групп и установка из готового архива с fake ADB. На собственном RUS H97x/build 650 установлен новый APK, штатные APK сохранены, радиослужба не перезапускалась. Пользователь проверил отправку по кнопке: серверный ZIP совпал побайтно. Внешний цикл сна/поиска ещё требует подтверждения. Актуальные результаты — в EVIDENCE.md.

Известные вопросы: сохранение частоты после стоянки, причина холодного запуска ГУ и полный цикл поиска станций. Индикатор справа в штатном интерфейсе может отображаться при пустом списке станций; это не индикатор буферизации звука. Автовоспроизведение после пробуждения зависит от штатного поведения и настроек Tweaks.

## Сборка и проверки

Если экран радио мешает открыть диагностику, отдельный Windows-сборщик создаёт новый ZIP прямо на ПК:

[Скачать готовый сборщик для Windows](https://github.com/kirbush/VoyahFree-SportPlus-radio-resurrection/raw/refs/heads/main/downloads/Voyah-FM-PC-Collect-2.zip).

1. Распаковать полный пакет `Voyah-FM-PC-Collect-2.zip`.
2. Подключить ГУ по USB и запустить `Collect-FM-now.cmd`.
3. Выбрать папку на ПК и дождаться `COLLECT_OK`.

Закрывать радио и предварительно создавать ZIP на ГУ не требуется. Сборщик читает текущий стек Activity/окон, существующие события FM, снимок помощника, crash buffer и записи DropBox нужных FM-приложений. Если root недоступен, отчёт явно помечается как ограниченный. Приложения, станции и системные файлы не изменяются. Исходники — `work/fm-loader/Collect-FM-*`; упаковка — `package_pc_collect.py`, проверка — `test_pc_collect.py`. Готовый пакет поставляется отдельно от установщика беты.

В Collect-2 доступна отправка на сервер: полученный отдельно `upload.json` кладётся рядом с CMD. `UPLOAD_SENT` подтверждает получение ZIP; при сетевой ошибке файл сохраняется в очереди и отправка повторяется при следующем запуске. Без приватной конфигурации работает обычный локальный сбор. Публичный ZIP не содержит ключей доступа. [Протокол, ограничения и состояние интеграции](work/fm-loader/upload/README.md).

Текущие скрипты рассчитаны на Windows и локально подготовленные инструменты. Репозиторий содержит исходники; для сборки нужно отдельно подготовить:

1. Python 3, Node.js и Git for Windows с Bash. Путь Node.js в `verify_offline.py` пока привязан к исходной машине разработчика.
2. JDK 17: `work/toolchains/jdk/jdk-17.0.21-lite/bin`.
3. Android SDK: `work/toolchains/build-tools/android-14` с `aapt.exe`, `zipalign.exe`, `lib/d8.jar`, `lib/apksigner.jar`; `work/toolchains/platform/android-11/android.jar`.
4. Оригинальные `AdayoDAB.apk`, `RdsApp.apk` и `frida-inject` 16.5.9 arm64 в `work/fm-loader/assets/`. Контрольные суммы указаны ниже.
5. Ключ `work/fm-loader-signing.p12` с alias `fmloader` и пароль в `work/fm-loader-signing.password`. Для обновления уже установленной беты нужен прежний ключ. Ключ и пароль не публикуются.
6. ADB 35.0.2 для Windows в `work/installer/package/adb/`: `adb.exe`, `AdbWinApi.dll`, `AdbWinUsbApi.dll`, `NOTICE.txt`.

Создайте локальные каталоги `outputs` и `work/fm-loader-validation`, затем из корня:

```powershell
python work/fm-loader/verify_offline.py
python work/fm-loader/build_beta.py
python work/fm-loader/package_beta.py
python work/fm-loader/test_beta_package.py
```

Результат: `outputs/Voyah-FM-0.5.0-beta-Windows.zip`. Проверка готового пакета использует подставной ADB и не обращается к автомобилю. Скрипты `build.py`, `package_final.py` и `package_tester.py` относятся к старому тестовому приложению; для текущей беты используйте команды выше.
