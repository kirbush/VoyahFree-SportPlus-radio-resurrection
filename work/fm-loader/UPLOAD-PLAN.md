# Автоотправка FM-отчётов

Цель: тестеру не нужно пересылать ZIP вручную. ГУ и PC-сборщик используют один HTTPS-приёмник. Локальная копия сохраняется при сетевых ошибках.

## Реализация

1. Отдельная WSGI-служба под непривилегированным пользователем, только loopback; существующий nginx проксирует отдельный URL. Сертификат и его продление уже настроены.
2. PUT готового ZIP по SHA-256, отдельный upload-only ключ клиента в заголовке. Повторы возвращают тот же идентификатор. Скачивания, списка файлов и команд для автомобиля в API нет.
3. Проверка размера, содержимого ZIP и контрольной суммы; атомарная запись, ограничение объёма/частоты, очистка только собственных старых отчётов. Ключи и реальные отчёты вне Git.
4. PC-сборщик после сохранения ZIP отправляет его при наличии отдельной приватной конфигурации. Сетевые ошибки оставляют копию в очереди; повтор при следующем запуске. Установка приложений и команды FM не добавляются.
5. ГУ: в следующем обновлении backend — отдельная очередь/исполнитель отправки, не блокирующий аппаратный health tick; периодические снимки и отчёты по кнопке. Конфигурацию переносит ADB-установщик. Текущая бета 0.4.3 и её испытание пока сохраняются: пользователь просил сначала собрать второй отчёт.

## Проверка

- Реальные WSGI-запросы: авторизация, валидный ZIP, повтор после потери ответа, неверный хеш, повреждённый архив, ограничение размера/объёма, отсутствие чтения/обхода путей, параллельные загрузки.
- Настоящий PowerShell с локальным HTTPS-приёмником: успешная отправка, отказ авторизации, потеря сети/ответа, сохранение ZIP и повтор очереди. Старые fake-ADB сценарии сохраняются.
- На сервере: синтаксис nginx/systemd, служба после restart, синтетический ZIP через публичный HTTPS, недоступность чтения, проверка прежних служб. Настройки до изменения сохраняются для отката.
- Живой тест Android пока не заявляется; логирование с одними заголовками требует отдельного исправления.
