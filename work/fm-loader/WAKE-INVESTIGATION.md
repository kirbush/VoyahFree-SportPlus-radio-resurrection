# Следующий этап: заставка и восстановление станции

Текущая бета остаётся0.5.1/code9. Продуктовый адаптер/оригинальные APK не менялись.

## Что установлено статически

В7.3.1/build35 PowerManager передаёт сброс состояния анимации службе bootcontrol
при SHUTDOWN_PREPARE. Затем native BootControl может снова запустить renderer
по ACC/PEPS, без нового запуска Android. Есть отдельная ветка «Play boot anim by STR».
Это объясняет техническую совместимость заставки и сохранённых процессов,
но НЕ подтверждает этот маршрут на живой7.2/build18 и НЕ измеряет глубину сна.

Контрольные компоненты7.3.1:
- PowerManager APK SHA256 f428c0960dac146dd38ba465c1b7dd873c653af62a86b1d7351531be5c399a42.
- /system/bin/bootcontrol SHA256 59dffa2d62286826ed0b73fbf50e78445a36f0c415aaa121c79ebfb9a11ce537.
- /system/bin/bootanimation SHA256 69571ab768258d3b09f4c59e092a54156a4b7e86a699d021a86bc51bf1348d50.

Сброс101.2→87.5 проходит через Java UART parser b.a.a.e.a.b.K и DABService$e.j.
Один callback используется для свежей частоты и для воспроизведения кэшированной
частоты при завершении сканирования. Старый FM-фильтр не сохранял сообщения
этого парсера: его log tag — обфусцированное «b». Поэтому прежний отчёт не
различает два пути. U=true приходит до отложенной конфигурации/ACK и не является
надёжным моментом для настройки частоты.

## Готовое наблюдение

Отдельный PC Collector3 читает полные доступные кольца power/FM-protocol ДО
медленных снимков, затем получает OEM power/bootcontrol без аргументов,
car_service power history, compositor layers, PID/startticks, suspend stats,
точные хеши компонентов и STR/power config. Ошибки доступа дают ограниченный
снимок, а не изменение политики. Сборщик не вводит trace hooks, команды станции,
перезапуск служб или изменение настроек. Общая запись FM продолжает работать.

Тестерская инструкция одна: pc-collect-3/ИНСТРУКЦИЯ.txt. Персональные архивы
с upload.json локальны; публичный архив содержит только пример конфигурации.
Первый новый отчёт должен быть собран сразу после возврата с заставкой,
без предварительного изменения частоты и с отключённым ПК во время стоянки.
Пустой исторический лог/отсутствие слоя после заставки не доказывают её отсутствия.

## Как выбирать следующую правку

- Совпавшие точные компоненты7.2 с эталоном и цепочка reset/play STR при сохранённых
  процессах подтвердят OEM-повтор анимации. Это не основание скрывать логотип.
- Смена system_server/SurfaceFlinger/startticks при том же bootID указывает на
  другой уровень перезапуска. Новый bootID подтверждает запуск ядра.
- Сообщение newFMFreq 001 отличает свежую UART-индикацию от scan-finish006 с кэшем;
  отсутствие строки при выключенном логе/переполнении не доказывает отсутствие.
- Если требуемый путь не попал в доступные кольца, следующий шаг — узкая
  структурированная трасса UART callbacks/ACK; только потом shipping fix.

Кандидат для станции — одно восстановление на эпоху USB reconnect после
завершения конфигурации/свежего состояния, с отменой при ручном выборе/seek/scan,
новом detach или смене источника. Состояние паузы нужно снимать ДО оригинального
detach, который принудительно её выставляет. Tune-only D0(freq) статически не
вызывает play/focus/PCM, но его фактическое влияние на mute требуется проверить.
Нельзя просто подавлять8750, бесконечно перенастраивать, считать setter успехом,
перезапускать Adayo или включать autoplay.

До интеграции: записанная10120/8750 последовательность; ручная8750 и новаястанция
побеждают; pause/source change сохраняются; поздняя конфигурация и кэшированные
ответы не запускают tune; matching ACK завершает один запрос, timeout не повторяет;
ни одного вызова lifecycle/PCM/play/focus из восстановления/экспорта.
