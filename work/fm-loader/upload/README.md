# Приём FM-отчётов

Сервер принимает готовые ZIP через HTTPS. PC-сборщик Collect-2 отправляет их после успешного локального сохранения. Фоновая отправка с ГУ пока запланирована для следующей беты; APK 0.4.3 не изменены.

## Доступ

У каждого тестера отдельный случайный ключ только на загрузку. В конфигурации сервера хранятся SHA-256 ключей, в приватном `upload.json` клиента — endpoint, client и token. SSH-ключ администратора в клиентскую конфигурацию не входит.

Публичный пакет содержит `upload.example.json`, а готовый `upload.json` разработчик передаёт отдельно. Его нужно положить рядом с `Collect-FM-now.cmd`. Автоотправка включается только при наличии этого файла. В Git и публичном ZIP действующих ключей нет.

## API и ограничения

- `PUT /voyah-fm/v1/reports/<sha256>` с `Authorization: Bearer ...`, `Content-Type: application/zip`, `X-FM-Source` и `X-FM-Report-Name`.
- Ответ 201/200 содержит `ok`, `id`, `sha256`, `bytes`. Повтор одного файла в рамках клиента не создаёт дубликат. Клиент удаляет копию из очереди после проверки всех полей подтверждения; исходный ZIP на ПК сохраняется.
- API не отдаёт список или содержимое отчётов, не удаляет их и не исполняет команды. Внутренние auth/health URL публично не проксируются.
- Nginx проверяет авторизацию до чтения тела запроса. Ограничены запросы, соединения, время и размер тела. Waitress слушает только loopback; отдельный системный пользователь не имеет root, capabilities или права изменять системные файлы.
- Архив не извлекается на диск. До разбора ограничиваются размер центрального каталога и число записей; ZIP64 не принимается. Независимо проверяются фактический размер распакованного потока, CRC и завершение deflate, включая архивы с Java data descriptors.
- Тело ZIP — до 16 MiB, суммарное содержимое — до 64 MiB. Только фиксированные текстовые файлы FM. Общая квота — 512 MiB, до 30 новых отчётов на клиента в час. Собственные завершённые отчёты старше 30 дней удаляет ежечасная уборка.
- Данные находятся в приватном каталоге вне web-root. Владельцу сервера доступна работа с ними по SSH; приёмник не предоставляет HTTP-интерфейс чтения.

## PC-очередь

`%LOCALAPPDATA%\Voyah-FM\upload-queue` содержит отдельную очередь для пары endpoint/client. Лимит — 32 ZIP / 64 MiB; старые неотправленные файлы не вытесняются. Даже заполненная очередь пытается выгрузить старые файлы при восстановлении сети. Подтверждения ограничены 128 последними записями. Одновременные экземпляры защищены mutex.

`UPLOAD_SENT` — сервер подтвердил текущий ZIP. `UPLOAD_QUEUED` — файл сохранён, повтор будет при следующем запуске сборщика. `UPLOAD_QUEUE_FULL`, `UPLOAD_CONFIG_ERROR` и `UPLOAD_BUSY` нужно сообщить разработчику; исходный ZIP остаётся в выбранной папке. Сбор логов считается успешным независимо от сети. Настоящий ADB в локальных тестах не используется.

## Развёртывание

Референсные файлы: `server.py`, `requirements.txt`, `voyah-fm-upload.service`, `nginx-http.conf`, `nginx-location.conf`. Сначала проверяются существующие слушатели и маршрутизация nginx, сертификат/продление и свободное место. Копии текущих настроек сохраняются до изменений. HTTP-level зоны и location-snippet подключаются в подходящий существующий HTTPS server; проверка `nginx -t` предшествует reload. Внешний порт backend не открывается.

Waitress устанавливается в отдельное окружение. Код и окружение принадлежат root и недоступны на запись службе; `clients.json` читается только root и группой службы. Каталог данных — 0700, файлы — 0600. Systemd ограничивает память 256 MiB, CPU 50%, задачи 32; `/tmp` отдельный, до 64 MiB.

Проверки: `python work/fm-loader/tests/test_upload_receiver.py`, `python work/fm-loader/tests/test_upload_pc.py`, общий `verify_offline.py`, затем `test_pc_collect.py --package <ZIP>`. Реальный HTTPS проверяется синтетическими отчётами, включая недоступность/восстановление службы, авторизацию и проверку закрытого чтения. На ГУ новая версия пока не проверялась.
